# 扩展首页路由设计

## 背景

OpenClacky 的 `/#new` 是 WebUI 默认入口。扩展已经可以注册完整工作区，并通过
`/#ext/<工作区 ID>` 打开，但宿主目前不能把某个扩展工作区设为首页。

`qingshi-workbench` 注册了自己的工作区，也重新组织了宿主导航，但它无法控制顶部
Logo 等宿主入口，所以点击 Logo 后仍会回到原生 `/#new` 页面。

## 设计决定

保留 `/#new` 作为 OpenClacky 唯一的首页入口，不新增 `/#home`，也不允许扩展自行
拦截或改写 `/#new`。

宿主进入 `/#new` 时，按以下顺序决定实际首页：

1. 用户明确选择且当前有效的扩展首页；
2. 用户没有明确选择，同时只有一个扩展首页候选时，自动使用该候选；
3. 其他情况显示原生新会话页面。

如果存在多个候选且用户尚未选择，宿主继续显示原生页面，直到用户作出选择。这样既能
让只有一个工作台的用户开箱即用，也能避免多个扩展按照加载顺序争抢首页。

跳转后，浏览器地址应显示实际目的地。例如青狮工作台生效后，访问 `/#new` 会进入
`/#ext/qingshi-workbench`。这样刷新、浏览器前进后退和深链接继续沿用现有工作区行为。

## 扩展协议

扩展可以把一个已经成功注册的工作区声明为“首页候选”。声明只提供候选信息，无权直接
导航或改写宿主路由。

候选信息至少包括：

- 工作区 ID；
- 英文名称；
- 中文名称；
- 所属扩展 ID（由宿主记录，不由扩展伪造）。

宿主只接受已经注册成功、当前启用且可用的工作区。

扩展不得：

- 自行拦截 `/#new`；
- 给宿主 Logo 添加点击处理；
- 未经用户操作把自己保存为明确选择；
- 根据加载顺序认定自己是默认首页。

## 解析规则

进入 `/#new`、首次启动、点击顶部 Logo，以及其他宿主入口返回首页时，都使用同一套
解析规则。

| 当前状态 | 实际首页 |
| --- | --- |
| 用户选择了一个当前有效的候选 | 选中的扩展工作区 |
| 没有明确选择，且只有一个候选 | 唯一的扩展工作区 |
| 没有明确选择，且有多个候选 | 原生新会话页面 |
| 没有任何候选 | 原生新会话页面 |
| 已保存的候选当前不可用 | 忽略失效选择，按上述规则重新解析 |
| 开启纯净模式 | 原生新会话页面 |

“唯一候选自动使用”不能写入用户明确偏好。安装第二个首页候选后，如果用户从未手动选择，
系统应回到原生页面让用户选择，而不是继续让第一个扩展自动占据首页。

## 用户体验

设置中提供“默认首页”选项，但只在存在扩展候选时显示：

- 没有候选：不显示额外设置；
- 一个候选：自动使用，同时允许用户明确切回原生首页；
- 多个候选：列出原生首页和全部有效候选，供用户单选。

用户明确选择“OpenClacky 原生首页”后，即使当前只有一个扩展候选，也必须尊重该选择，
不能再次自动跳转。

## 异常与恢复

首页解析由宿主负责，并始终以原生页面作为安全回退：

- 候选扩展被禁用或卸载时，重新解析剩余候选；
- 工作区注册失败时，不能把它视为有效候选；
- 工作区渲染失败时，用户仍应能回到原生页面；
- `?pure=true` 必须完全绕过扩展首页；
- 无效偏好不能造成 `/#new` 与 `/#ext/...` 之间的循环跳转。

宿主可以保留暂时失效的用户偏好，以便扩展重新安装后恢复，但扩展不可用期间必须忽略它。

## 青狮工作台的定位

`qingshi-workbench` 不是本项目维护的扩展，不纳入正式交付范围。开发时可以临时修改本机
已安装副本，让它注册为首页候选，用来验证宿主能力是否生效。

这类修改仅用于本地测试：

- 不提交到 `openclacky`；
- 不作为青狮工作台正式改造方案；
- 不打包或发布修改后的第三方扩展；
- 测试完成后记录改动位置，方便恢复或由重新安装覆盖。

未来该扩展若要正式接入，应由其维护者在源码仓库中调用宿主提供的首页候选接口。

## 验收场景

1. 没有候选时，访问 `/#new` 显示原生新会话页面。
2. 只有青狮工作台一个候选且没有明确选择时，访问 `/#new` 自动进入
   `/#ext/qingshi-workbench`。
3. 青狮工作台是实际首页时，点击顶部 Logo 仍进入青狮工作台。
4. 有两个候选且没有明确选择时，访问 `/#new` 显示原生页面。
5. 用户从多个候选中选择一个后，刷新和再次访问 `/#new` 都进入该工作区。
6. 用户明确选择原生首页后，即使只剩一个扩展候选，也显示原生页面。
7. 选中的扩展被禁用或卸载后，不发生循环跳转，并安全回退。
8. 使用 `?pure=true#new` 时，始终显示原生页面。

## 范围边界

本次只修改首页解析和扩展 UI 协议，不替换原生新会话功能，不改变会话创建流程，也不允许
扩展覆盖其他宿主路由。
